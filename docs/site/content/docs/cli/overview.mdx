The Coding Agent 2 CLI is the `orca` command-line interface for scripting a running Coding Agent 2 editor from any shell. Use it to create and inspect worktrees, drive agent terminals, open files and diffs, automate the built-in browser, run scheduled automations, share HTML/Markdown artifacts, and control Coding Agent 2-native tools from scripts or AI agents.

It ships with the desktop app; register it under [Settings → General → Coding Agent 2 CLI](/docs/settings). On Linux the command is `orca-ide`, because GNOME Coding Agent 2's screen reader already owns `/usr/bin/orca` — see [Install → Linux](/docs/install#linux).

Agents can install the matching Coding Agent 2 CLI skill with:

```bash
npx skills add https://github.com/stablyai/orca --skill orca-cli
# headless / no Settings UI:
coding skills install --skill orca-cli
```

See [Skills registry & MCP](/docs/cli/skills) for every installable Coding Agent 2 skill, including `coding skills install` / `coding skills update`.

## Install & verify

```
command -v orca
coding status --json
```

## Worktree commands

```
coding worktree ps --json
coding worktree create --repo id:<repoId> --name my-task --issue 123 --json
coding worktree create --repo id:<repoId> --name review-pr-123 --pr 123 --json
coding worktree current --json
coding worktree set --worktree active --comment "reproduced bug" --json
coding worktree set --worktree active --gitlab-issue 42 --gitlab-mr 77 --json
coding worktree set --worktree active --pr null --json
coding worktree rm --worktree id:<id> --force --json
```

For selectors, setup flags, parent/child worktrees, and the broader command map, see [Coding Agent 2 CLI reference](/docs/cli/reference).

## Terminal commands

```
coding terminal list --json
coding terminal read --json
coding terminal send --text "continue" --enter --json
coding terminal wait --for tui-idle --timeout-ms 30000 --json
coding terminal create --worktree path:/projects/app --command "npm test" --json
coding terminal split --direction vertical --command "npm run dev" --json
```

For tracked multi-agent work, use [Orchestration](/docs/cli/orchestration) instead of plain terminal prompts.

## File commands

Open files and diffs as tabs in their Coding Agent 2 worktree from a shell. They open without changing what you are looking at; add `--focus` to be brought to the file:

```
coding file open src/App.tsx
coding file diff src/App.tsx --staged
coding file open-changed --mode both
```

Use `--worktree <selector>` when the shell's current directory is not inside the target worktree.

## Browser profiles

Browser profiles isolate tab session state, so a script or agent can test with different cookies, local storage, and logged-in identities. The CLI exposes profile commands under `coding tab profile`; start with `coding tab profile list --json`, then use `create`, `set`, `clone`, or `use-default` as needed.

## Scheduled automations

Use `coding automations` to create, inspect, run, and remove scheduled Coding Agent 2 tasks from a shell. Start with [Scheduled automations](/docs/cli/automations) when you want a recurring prompt to run against a repo or an existing worktree.

## Artifacts

Share HTML or Markdown as public view links through the signed-in Coding Agent 2 account (`coding artifacts share|update|list|delete`). Publishing is **opt-in** under Settings → Artifacts. Command details: [CLI reference → Artifacts](/docs/cli/reference#artifacts).

## Browser automation

The CLI also drives the built-in browser with a snapshot-interact-re-snapshot loop:

```
coding goto --url https://example.com --json
coding snapshot --json     # returns refs like @e1, @e3
coding click --element @e3 --json
coding fill --element @e1 --value "user@example.com" --json
coding screenshot --json
```

For responsive browser checks, switch the active tab to a named device profile:

```
coding set device --name "iPhone 12" --json
coding screenshot --json
```

## Mobile emulator

The CLI can also drive an iOS Simulator through Coding Agent 2's mobile emulator bridge. It is scoped to the active worktree, so agents and scripts can attach a simulator, list the worktree's attached devices with `coding emulator list`, tap normalized coordinates, type text, send gestures, rotate the device, and shut it down without leaving Coding Agent 2.

```
coding emulator list --json
coding emulator attach "<device-name-or-udid>" --json
coding emulator tap 0.5 0.7 --json
coding emulator type "hello" --json
coding emulator gesture '[{"type":"begin","x":0.5,"y":0.8},{"type":"move","x":0.5,"y":0.4},{"type":"end","x":0.5,"y":0.2}]' --json
coding emulator rotate landscape_left --json
coding emulator kill --json
```

Use `--worktree <selector>`, `--device <udid-or-name>`, or `--emulator <id>` when a script needs an explicit target.
